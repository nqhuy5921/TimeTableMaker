# Card Pool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cards become one pool for the whole school: any card can go on any class's grid, a card's classes come from its placements, and the Cards page shows Subject · Teacher · Room · Classes · actions.

**Architecture:** `Card` loses `classId` and `Placement` gains it (file format version 2, with a migration that merges identical cards). Every per-class question (slots, placed counts, periods per subject) reads `placement.classId`. The renderer shows the whole pool in the Subjects panel and passes the class on screen to `drop`.

**Tech Stack:** TypeScript, React 19, dnd-kit, zod 4, Vitest, Playwright (Electron).

**Spec:** `docs/design/SYSTEM_DESIGN.md` §3a, and DM-5, DM-7 in `docs/requirements/01-data-management.md`, TB-1, TB-3–TB-5 in `docs/requirements/02-timetable-builder.md` (all changed and approved 2026-10-21).

## Global Constraints

- No version control in this folder: there are no commit steps. Don't run `git init`. The model change in Task 1 breaks its callers until Task 3, so Tasks 1–3 run back to back in one sitting: each ends with its own tests passing, and `npm run check` plus the e2e tests must pass at the end of Task 3 before anything else.
- Domain rules live in `src/domain/` with unit tests in `tests/domain/`; no React or Electron there.
- Made-up data only in fixtures and tests (no names from the reference workbook).
- E2E tests run with `xvfb-run -a -s "-screen 0 1920x1080x24" npm run test:e2e` while the screen may be locked.
- UI copy is English. Design tokens only, no literal colors (`src/renderer/styles/tokens.css`). Numeric cells get `tnum`.
- Duplicate-card message, exact: `There's already a card for <subject> with <teacher> in <room>.` — with "no teacher" and "no room" when empty, e.g. `There's already a card for Toán with no teacher in no room.`
- Cards page empty Classes cell, exact: `Not placed`, in `--ink-mute`.
- "Add subject" keeps its label in the Subjects panel.

## Review Focus

1. **The user's real v1 file loads** with every placement on the same class, day, block, and part, and identical cards merged — Task 1's migration test uses a v1 file with two identical cards in two classes.
2. **Editing a card into a copy of another** is refused, never silently merged — Task 2 test `editCard refuses a subject, teacher, and room another card has`.
3. **Moving a placed card never changes its class**, even though the card is on several grids — Task 2 test `movePlacement keeps the placement's class`.
4. **Two cards of one subject on one grid** give one "Periods per subject" tag with the sum, and no duplicate React keys — Task 2 test in `periodsBySubject`, Task 3 e2e step.
5. **Deleting a card on several grids** removes it from all of them and the question names every class — Task 2 test in `deleteCard`, Task 3 e2e in `cardsPage.spec.ts`.
