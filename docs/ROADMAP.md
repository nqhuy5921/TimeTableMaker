# Roadmap

The order of work, in small steps that each leave the app working. The `next-step` skill (`.claude/skills/next-step/`) keeps this file current: when a step is done it ticks the step, moves **Next step**, and shows what comes after.

**Next step:** R5-7 — Release 5 review

How to read a step:

- **Covers:** the requirements it delivers. A step isn't done until every acceptance criterion it covers has a test.
- **Build:** what gets made.
- **Done when:** how to check it. Every step also needs `npm run check` and `npm run test:e2e` to pass, `CHANGELOG.md` updated, for UI work the app opened and looked at, and a `/code-review` of the step's changes with its findings fixed before the step is ticked (the user asked on 2026-10-22).
- **Gate:** anything the user has to approve before the step starts.

Status: `[x]` done (with the date), `[ ]` not started, `[~]` in progress.

### [x] R1-2 — Saving (2026-10-19)

- **Covers:** TB-7.
- **Built:**
  - Main process: read and write `timetable.json` in `userData` through the IPC contract. It writes a temp file and renames it, keeps `timetable.json.bak`, and finishes a pending save before the window closes.
  - Renderer: saves after each change, at most once every 500 ms.
  - Loading: checks the file with zod and upgrades older `schemaVersion`s. If the file is damaged it says so, offers the backup, and never overwrites the damaged file.
  - As built (`src/main/store.ts`, `src/shared/fileFormat.ts`, `src/renderer/state/saveScheduler.ts`): the window asks the renderer to finish its pending save before it closes, waiting up to 3 seconds. A damaged file blocks saving until the user picks "Open the backup" or "Start a new timetable", and both rename it to `timetable.damaged-<date>.json`. A failed save shows a message until the next one works.
  - The class on screen is remembered in `settings.json` (the user's choice on 2026-10-19), and the app opens on the first class by grade when there's none.
  - Tests: `tests/main/store.test.ts`, `tests/main/fileFormat.test.ts`, `tests/renderer/saveScheduler.test.ts`, `tests/domain/appState.test.ts`, `tests/e2e/saving.spec.ts`.
